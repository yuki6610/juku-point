【新規実装・機能追加】

2. シフト作成
現在Numbers / Excelで作っているシフト表をアプリ化する。
シフト表は1週間単位（月〜土）。日曜は休み。
作成方法は「自動生成＋直接編集」の併用。
通常授業・講習・振替などの確定授業からシフトを自動生成し、その後Numbersのように表上で、講師変更／時間変更／生徒追加／生徒移動などを直接調整できるようにする。
編集するシフトは4週分。生徒と講師の予定はほぼ固定なので、すべてコピーベースを編集する。

3. シフトから担当生徒を自動選択
アプリ内シフト作成が完成したら、講師が当日アプリを開いた時点で、その日の確定シフトに入っている生徒を自動選択済みにする。
ただし、急な代講／追加授業／担当変更／イレギュラーに対応するため、講師は生徒を手動で追加・解除できる。
優先順位：予定シフト → 自動選択 → 当日の手動変更を優先
手動変更は当日中保持し、日付変更でリセットする。
当日途中に管理者がシフトを変更しても、講師がすでに行った手動変更を勝手に上書きしない。

11. 欠席・振替
保護者マイページから欠席連絡を入力可能にする。
振替希望時には、講師の出勤可能時間／既存授業／対応教科／同時指導可能人数／教室側の空きなどを照合して候補を出す。
確定した振替は、講師シフト／生徒・保護者カレンダー／授業予定／学習記録へ自動反映する。
通常授業→欠席→振替の関係を追跡可能にする。
この機能はシフト作成機能と連携する。

12. 講師シフト希望
講師ページから出勤可能日時を入力する。また、指導可能教科と学年も入力する。
講習・面談で使っている「日付×時間帯UI」を再利用する。
管理者は複数講師の希望をまとめて確認する。
最終的には、講師希望／指導可能科目と学年／通常授業／講習／欠席／振替を組み合わせた動的シフト管理を目指す。

13. 生徒・保護者AIアシスタント
モデルはGPT-5.6 Luna。テキストのみ。
【生徒】今日の宿題／次回授業／カレンダー／数学・英語などの質問／宿題の解き方
学習質問は、ヒント → 考え方 → 解説 → 必要なら答えの順。
【保護者】今日営業しているか／次回授業／宿題／面談／講習／お知らせ／最近の授業状況など。

14. AIを使わない質問
Firestoreから直接答えられる、営業状況／次回授業／今日の宿題／面談期限／講習期限／所持ポイント／AI残り回数などではLunaを呼ばない。
AIを使うのは、学習解説／要約／複数データの分析／自然文章作成など。

15. AI利用制限
構想：5時間枠／週間枠／生徒ポイントによる追加／ポイントでも解除できない絶対上限／塾全体月間上限
具体的な回数・ポイント数は未確定。

16. AIバグ報告
生徒・保護者はAIアシスタントに自然文でバグ報告できる。
例：「宿題が表示されない」
AIは不足情報だけ1〜2問確認する。
自動取得候補：日時／ユーザー／role／現在ページ／端末・ブラウザ／アプリバージョン／エラー情報
ユーザー確認後にバグDBへ登録する。
状態：未確認／確認済み／対応中／対応済み
バグ報告はAI利用枠を原則消費しない。
ホーム画面の専用「バグ報告」ボタンは削除済み。

19. 本アカウント紐付け
現在、中学生には管理側で作った「仮メール＋仮パスワード」のFirebase Authアカウントがある。
管理画面に「本アカウント紐付け」ページを作る。
既存の生徒レコードは作り直さない。
studentIdを永続IDとして、生徒データとFirebase Auth uidを分離する。
可能なら既存uidを維持したまま、仮メール → 本人メール／仮パスワード → 本人パスワードへ移行する。

20. 小学生から中学生へのアカウント移行
小学生は管理者が生徒データだけ先に作る。
本人Authがなくてもよい。
中学生になって本人アカウントを作るとき、新しい生徒レコードを作らず既存studentIdへ紐付ける。
これにより、授業履歴／宿題／成績／保護者／メモなどを維持できる。

21. ログイン復旧
ログインできなくなった場合の復旧機能を追加する。
正式メールを持っていればFirebaseの再設定メールを利用。
仮メール等で自己復旧できない場合は、管理者が「ログイン復旧」から期限付き・一回限りの再設定リンク／QRを発行する。
実行者・対象ユーザー・日時を履歴に残す。

23. アプリ運用費
管理者がスマホからアプリ運用原価を確認できる機能を正式採用。
表示候補た：OpenAI今月累計／Firebase / Google Cloud今月累計／前月／今月予測／AI利用回数／トークン数／推定料金／実コストとの比較
APIキー・Admin Keyはクライアントへ渡さずサーバー側で取得する。
これは保護者への月謝請求とは別機能。


【既存機能の改善・仕様変更】

24. 講習授業の全面改修
現在の「講習申込→日程調整」が十分機能していないため全面的に作り直す。
講習管理は「講習専用の学習記録ページ」ではなく、「講習の申込・必要コマ数・日程を作る管理ページ」にする。
流れ：講習作成 → 保護者申込 → 受講コマ数確定 → 日程調整 → 開始時間設定 → 担当講師設定 → 管理者確認 → 講習授業確定 → 共通の授業予定へ登録 → 講師の「今日の授業」へ
管理画面は、申込状況／日程調整／確定授業などに整理する方向。
生徒ごとに、「30コマ中18コマ確定／残り12コマ」などを確認できるようにする。
日程調整では、1コマずつだけでなく2コマ連続などを簡単に登録できるUIにする。

25. 通常授業か講習授業か振替授業かの判定
管理画面ですでに1週間分のシフトと講習期間を設定しているため、それを利用する。
講習期間外には講習授業を選択欄に出さない
講習期間中は確定授業予定から通常授業／講習授業を自動判定。予定データだけでは判定できない場合のみ講師に選択させる
振替授業も自動で判定する。

26. 講師ページ「今日の授業」
同じ生徒が1日に複数授業ある場合、同じ生徒名が複数表示されても問題ない。
例：山田太郎｜通常｜17:00／山田太郎｜夏期講習｜18:40／山田太郎｜夏期講習｜20:20
同名だけを並べず、「生徒名＋授業種別＋開始時刻」で識別する。

31. 保護者ホーム
「最近の授業」は削除して。宿題の実施状況の短いコメントも削除して。
授業報告も専用タブがあるためホームには出さない。
学年表示、ホーム上のバグ報告ボタンとログアウトボタンも削除する。
ホームはお知らせを表示する。

32. 保護者ページ全体のUI統一
保護者ページは画面上から保護者マイページ、管理者さんの授業報告や予定をご確認いただけます、BETA、タブがある。画面の3分の1を占めているので、大きさ調整と不要なものを削除する。バグ報告とログアウトは削除。文章も削除。すべてのタブで同じUIにする。

33. 高校判定
テストや内申が未登録でも高校判定ページ自体を隠さない。
「未登録」「判定には追加情報が必要」などと表示する。

34. タグ
タグは「タグ一括管理」へ集約する。
生徒一覧では現在のタグをチップ表示する。
学年フィルタ後に一括付与・解除できる。
任意入力したタグもその場限りにせずタグマスターへ保存する。
同名タグは重複作成しない。
