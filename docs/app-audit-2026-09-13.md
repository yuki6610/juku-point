# その他の生徒・管理画面の調査

2026-09-13。アプリのコード・データを変更せず、読み取り調査と模擬データによる確認を実施。デプロイは行っていない。この文書のみ追加した。

## 重要な問題

### 1. 生徒の成績保存とアクセス制限が矛盾【優先度: 高】

`src/app/student/scores/page.js` の saveExam/saveInternal は users/{uid}/scores へ addDoc する。一方、現在の `firestore.rules` は users 以下の書き込みを管理者に限定しており、生徒用の scores 作成許可もない。現在のRulesで生徒が保存すると拒否される構成。管理者によるプレビューでは発見できない。

推奨: 生徒用の成績保存APIで本人・中学生・学期・得点・重複を検証する。Rulesを広く開放して対処しない。本番にどのRulesが公開されているかは今回未確認。

### 2. 宿題の訂正履歴が残高・再集計と一致しない【高／模擬実行で再現】

`src/app/api/admin/lesson-records/route.js` と `src/app/api/admin/rebuild-term-points/route.js`。

- 提出を宿題なしへ訂正すると、元の +50 の履歴を同じIDの -50 で上書き。残高は50→0で正しいが、この履歴を合計すると -50 になる。
- 途中を宿題なしへ訂正すると残高は75→100（+25）だが、履歴は固定で +50 と記録される。
- 再集計APIは履歴の amount を合計するので、この不整合が学期ポイントへ反映される。

実際の保存APIを、既存テストの模擬Firestoreで上記2条件にして実行し、書き込み内容を確認した。本番の記録は変更していない。

推奨: 「現在の有効報酬」と「訂正操作履歴」を分離し、再集計は有効報酬に統一。既存訂正履歴の補正は別途プレビュー・バックアップ後に行う。

### 3. 新学期切替が新学期の獲得分まで消す可能性【高／コード上の条件付きリスク】

`src/app/admin/page.js`、`src/app/utils/resetSeason.js`、自習・学習記録の保存API。

新学期開始は管理者の手動操作。開始前にも自習等は users の termPoints へ加算する。後から切替すると、その時点の全学期カウンターを旧学期として保存し0へ戻す。読み取り・初期化がトランザクションではなく、同時入力と競合する危険もある。

推奨: 学期IDごとの集計を保存し、学期切替は表示対象変更と締め処理に分ける。現在の本番集計に混在が起きているかは未確認。

### 4. 学期の単語得点ランキングが更新されない【高】

`src/app/ranking/page.js`、`src/app/api/ranking/route.js` は termWordScore を表示する。現在の学習記録保存APIは totalWordTestScore のみ更新し、termWordScore を更新していない。termHomeworkCount/termWordTestCount も同様。調査した src 内では該当学期カウンターの更新処理はリセット以外に見つからない。

また累計交換回数は旧 users.rewardHistory 配列の長さを使用し、新しい rewardHistory サブコレクションの交換を加算していない。

推奨: 保存時の学期集計とランキングの読み取り元を共通化し、既存分は再計算結果を先に表示して確認する。

### 5. 中学生の出欠削除が生活態度集計へ反映されない【高】

`src/app/api/admin/lesson-attendance/route.js` は出欠取消を共通記録・lessonTermsへ書くが、behaviorSummary は更新しない。`src/app/behavior/page.js` は behaviorSummary を読むため、保護者の統合履歴と生徒の生活態度グラフが一致しなくなる。

推奨: 削除・訂正も共通の集計更新を通す。今回修正済みの通常保存だけでは、この経路は解決しない。

## 履歴・長期運用

### 6. 生徒の交換履歴は旧・新形式の混在に非対応【中】

`src/app/rewards/history/page.js` は新サブコレクションが1件でもあれば旧配列を読まない。旧形式しかない場合も30件で切り取り、その先へ進む機能がない。date のないドキュメントも並び替えクエリから除外される。

管理画面の `src/app/admin/rewards/RewardHistory.js` では旧新の統合読み取りがあり、同じ生徒でも両画面の件数が異なり得る。生徒側にも互換読み取りとページ送りが必要。

### 7. ガチャ履歴と未引き渡し件数に件数制限の問題【中】

- `src/app/api/gacha/route.js`: 日時順を指定せず50件を取得した後に並べ替えている。最新50件ではない。pendingCountもこの50件内のみ。
- `src/app/api/admin/gacha/route.js`: 最新500件で固定。古い未引き渡しが対象外となり、合計・未引き渡し数も500件内だけになる。

推奨: 日時カーソルによる履歴取得と、未引き渡しを独立した条件で取得する。必要なインデックスも同時に管理する。

### 8. 生徒画面に固定年度・学期が残る【中】

- `src/app/behavior/page.js`: 年度は2024〜2026、初期値2026年1学期。
- `src/app/student/scores/page.js`: 年度は2025〜2028、初期値2026年1学期。
- `src/app/utils/season.js`: 2026年の期間を直書き、それ以外は月で判定。ランキングが使用する。
- `src/app/api/rewards/redeem/route.js`: 交換履歴の seasonId を同様の固定期間で判定する。

共通学期設定を変更しても、これらは追従しない。生徒側・交換APIも同じ設定を読む設計が必要。

### 9. 自習の退出忘れが日をまたぐと処理できない【中】

`src/app/api/checkin/route.js` は入室・退出とも「今日」のcheckinsだけを使用。前日の入室から日をまたぐと開始記録なしになる。`src/app/admin/study-log/CurrentStudy.js` も今日だけ読むため、前日の未退出が表示されず強制退出できない。

推奨: 現在有効な自習セッションを日付と独立して管理し、退出忘れを別枠で表示する。

### 10. 自習履歴は高校生を選べず、全期間を読む【中】

`src/app/api/admin/study-logs/route.js`: 生徒候補を中学生に限定し、履歴を全件取得。高校生の利用履歴を通常操作で選べず、長期運用では取得量が増える。高校生追加と期間・件数指定が必要。

## 入力・UI・運用

### 11. 管理者の成績入力に入力検証・編集導線が不足【中】

`src/app/admin/score/ScoreManager.js`:

- 生徒を変えても入力中の得点・学年をリセットしない。
- 得点を数字だけにする処理はあるが、空欄・100点超の保存検証がない。
- 更新処理用 editingScoreId は存在するが、それを既存成績IDに設定する編集ボタンがなく、一覧は削除のみ。
- 保護者が入力した成績も「生徒入力」と表示される。
- 保存中ロック、失敗時の画面内案内がない。

推奨: 選択生徒を強調し、未保存警告、既存成績からの編集、入力者の区別、保存前検証を追加する。

### 12. 生徒メモが更新操作で消え、同時編集に弱い【中】

`src/app/admin/student-notes/page.js` の「最新に更新」は全行を取り直して未保存編集を上書き。`src/app/api/admin/student-notes/route.js` は版番号なしで全メモ項目を上書きする。

講師メモは学習記録の保存時に1つの teacherMemo へ上書きされるため、過去授業の訂正が最新授業のメモを上書きする場合もある。

推奨: 未保存行の表示、更新前の警告、行単位の版管理、講師メモの日付順履歴を設ける。

### 13. 退塾状態の扱いがページごとに異なる【要仕様確認・中】

生徒管理は active/enrollmentStatus を変更するが、通常ランキングと夏期イベントランキングには退塾除外がない。景品交換・ガチャ・自習APIも在籍状態を確認しない。

退塾を「履歴は保持し、新規利用を停止する」意味とするなら、UIだけでなくサーバー側の共通チェックが必要。残ポイントの交換を認める猶予期間の有無は運用方針を決める。

### 14. 自習退出の保存と警告ログが別処理【中】

`src/app/api/checkin/route.js`: 退出・ポイント付与の完了後、教室外退出ログを別途保存する。そのログだけ失敗すると、実際は退出済みなのにAPIはエラーを返す。

推奨: 警告ログも同一トランザクションに含め、保存結果を一意にする。

## コード上で確認できた良い点

- 景品交換とガチャは残高・在庫をトランザクションで更新し、学期ポイント・累計獲得ポイントを消費で減らさない。
- 夏期イベントのランキングは管理者を除外している。
- 自習はサーバーでも100m制限を判定し、退出の距離超過は拒否でなく警告扱い。
- 授業カレンダーは共通設定の年度と学期範囲から表示する構造で、将来年度の選択導線がある。
- 管理者ページには共通権限確認があり、主要サイドバーの移動先は統合後のページに対応している。

## 推奨順序

1. ポイント訂正履歴と再集計、新学期切替の安全性。
2. 生徒の成績保存、出欠取消後の集計、ランキングの更新漏れ。
3. 年度学期の残存固定値、旧交換履歴、ガチャのページ送り。
4. 自習の退出忘れ・高校生対応、退塾の利用制御。
5. 成績入力と生徒メモの誤操作防止・UI改善。
